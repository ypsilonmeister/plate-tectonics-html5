# 原本（Java）との動作比較

元の jar のモデルクラスを画面なしで直接動かし、HTML5 版のモデルと同じ操作をして、結果を数値で突き合わせます。

```bash
cd verify
javac -nowarn -cp ../plate-tectonics_ja.jar -d out JavaDump.java
java --add-opens java.base/java.lang=ALL-UNNAMED -Djava.awt.headless=true -cp "../plate-tectonics_ja.jar;out" JavaDump > java.json
node js-dump.js > js.json
node compare.js            # --verbose で全件表示
```

(macOS / Linux ではクラスパスの区切りを `;` ではなく `:` にします。Java 17 で確認済み。)

## 比べている内容

- **プレート運動**: 地殻 3 種 × 3 種 × 動き 3 種のうち、元の版で選べる 22 通りと、トランスフォームの逆回転 6 通り。計 28 通りを 0.1 秒刻みで 600 ステップ（時間の上限まで）進め、50 ステップごとに比べる
  - 全領域の全サンプル点の位置・温度・密度、地形の高さ、ラベルと噴煙の数、時間と上限
  - 画面全体 165 点での密度計・温度計の値
- **地殻タブ**: 温度・構成・厚みの 6 通りの設定。アイソスタシーで落ち着くまで進め、同じ内容を比べる

マグマや噴煙は `Math.random()` を使うので、Java 側は乱数生成器を取り出して種を固定し、JS 側は同じアルゴリズム（`java.util.Random`）で同じ数列を再現しています。

## 結果

28/28 通りと地殻タブ 6 通りすべてで一致（誤差は Java の 32bit float 計算の範囲）。

計器の値で違ったのは、測定点が三角形の辺のちょうど上にある場合だけです。Java の当たり判定は float で計算するため、辺の上では外れて「水」の値を返します（地下なのに水の密度になる、原本側の誤差）。少しずらした点では一致するので、比較から除外しています。

## 画面の見た目

`node shoot-html5.js`（`html5/` を http://localhost:8765 で配信した状態で実行）で、原本の描画領域と同じ 1165×645 の HTML5 版スクリーンショットを `shots/` に保存します。原本と並べて比べた場面: 地殻タブ（密度表示、温度表示＋名称）、プレート運動タブ（空の状態、大陸地殻と古い海洋地殻を置いた直後、自動モードで沈み込み 50 百万年）。これに合わせて直したもの:

- 置き場の枠: 黒の点線（`glLineStipple(1, 0xFF00)`）で 12 辺すべて
- ツールボックス: 定規を左端に 0.5 倍、温度計と密度計を 0.75 倍で下揃え。アイコンの温度計は空、密度計は針ゼロで数値なし
- 手動モードの「経過時間」: 左端を「ステージ幅 − 自動モード時のパネル幅 − 10」に置く（原本の `moveTimeControl` が false の場合）
- 速度スライダー: 0.1〜10 倍の直線目盛、初期値 1 倍
- 地表の陰影: 太陽 (1,3,2) と月 (-2,1,-1) の 2 灯 + 環境光 0.04。太陽だけだったため、地表が約 3 割暗かった

原本（OpenGL）は最大化すると、画面取り込みの絵が更新されなくなります。比べるときはウィンドウを最大化しないでください。また原本は、外から送ったドラッグ操作を受け付けません（地殻ブロックは手で置く必要があります）。発散の場面はまだ原本と並べて比べていません。

この比較で見つかって直したもの: `recursiveSplitCall` が Java の float 比較と違い、0.1 秒の刻みを余分に半分に分けていたため、大陸の発散で地殻が最大約 600m ずれ、沈み込みでマグマと噴煙の数が変わっていた（`html5/js/core.js`）。
